# Etrx

## Данные лестницы задач

Маршруты каталога и статистики доступны гостю.

| GET | Что возвращает |
| --- | --- |
| `/api/ladder/levels` | Доступные пары `division` и `difficulty` из каталога задач |
| `/api/ladder/ratings` | Реальные рейтинги задач выбранного `division`, без повторов, по возрастанию |
| `/api/ladder/difficulties` | Реальные сложности задач выбранного `division` и необязательного `rating`, без повторов, по возрастанию |
| `/api/ladder` | Теги с приоритетами и группы задач выбранного уровня |
| `/api/ladder/statistics` | По одной строке на участника и задачу, по которой есть импортированные посылки |
| `/api/ladder/participants` | Участники с именем, фамилией, числом уникальных решённых задач и списком этих задач |

Для всех перечисленных GET-маршрутов, кроме `/api/ladder/levels`, обязателен `division`. Для лестницы и отчётов `difficulty` и `rating` необязательны: без них возвращаются все сложности и рейтинги выбранного дивизиона. Передавай одинаковые фильтры в запросы лестницы и её статистики. Например, `?division=Div4&difficulty=1&rating=800&tags=implementation&tags=math`. Параметр `rating` задаёт точный рейтинг. Параметр `lang` выбирает язык названия задачи.

В интерфейсе сначала выбирается дивизион, затем необязательные рейтинг и сложность. Рейтинги берутся из `/api/ladder/ratings` для всего дивизиона, сложности — из `/api/ladder/difficulties` для выбранных дивизиона и рейтинга; «Любой рейтинг» и «Любая сложность» снимают соответствующее ограничение. Значение рейтинга 0 отображается как «Без рейтинга». Смена дивизиона сбрасывает рейтинг и сложность; смена сложности сохраняет выбранный рейтинг. После смены рейтинга сохраняется доступная сложность, а недоступная сбрасывается на «Любая сложность».

Без параметра `tags` возвращается весь уровень. При выборе нескольких тегов в лестницу попадают задачи, у которых есть хотя бы один тег и все теги входят в выбранный набор. Каждая комбинация образует свою группу. Внутри группы задачи идут по убыванию `solvedCount`.

Лестница на сайте загружает заголовки групп порциями по 8: `groupOffset=0&groupLimit=8&includeProblems=false`. Ответ содержит `totalGroups`, а каждая группа — `problemCount`. Следующая порция использует смещение 8, 16 и далее. При раскрытии группы сайт запрашивает её задачи с `groupOffset=<номер группы>&groupLimit=1&includeProblems=true`. Без этих параметров API сохраняет выдачу всего уровня. Сервер по-прежнему определяет порядок групп по тегам всего выбранного уровня, но названия и подробности задач читает только для запрошенных групп.

Для вошедшего пользователя `GET/PUT /api/ladder/preferences` восстанавливает и сохраняет фильтры лестницы. Формат записи: `{ "expectedHandle": "handle", "filters": { "division": "Div1", "difficulty": "1", "tags": "[\"math\",\"dp\"]" } }`. Разрешены `division`, `difficulty`, `rating`, `tags`; значения — строки, теги сериализуются как JSON-массив. Фильтры хранятся отдельно от раздела задач, в столбце `ladder_filters_json`. Перед выходом клиент дожидается сохранения обоих разделов. Новая миграция `AddLadderPreferences` добавляет столбец с пустыми настройками для существующих аккаунтов.

Для таблицы результатов соедини `groups[].problems[]` и строки статистики по паре `(contestId, index)`. Поле `handle` указывает участника, `attempts` считает его импортированные посылки, `solved` означает хотя бы один вердикт `OK`. Повторный `OK` увеличивает число попыток. `firstAcceptedAt` и `lastAttemptAt` содержат время в Unix-секундах UTC. До первого `OK` поле `firstAcceptedAt` равно `null`. Отсутствие строки означает ноль известных попыток.

### Решения участников по ветке

В раскрытой группе сайта ссылка «Кто решил задачи этой ветки (JSON)» открывает `/api/ladder/participants?division=Div4&tags=math&exactTags=true`. `exactTags=true` выбирает точное сочетание тегов ветки: для `math + dp` передай `tags=math&tags=dp`; без тегов это ветка «Без тегов». Необязательные `difficulty` и `rating` ограничивают задачи так же, как в лестнице. Параметры порционной загрузки на отчёт не влияют.

Без `exactTags=true` применяется та же выборка подмножеств тегов, что в лестнице; без тегов возвращается весь выбранный дивизион/уровень. Общая ссылка над списком групп ведёт на такой отчёт.

Ответ содержит `division`, `difficulty`, `rating`, `tags`, `exactTags`, `totalProblems` и `participants`. В каждой строке участника: `handle`, `firstName`, `lastName`, `solvedCount`, `solvedProblems`. У каждой решённой задачи: `contestId`, `index`, `name`, `rating`, `gym`, `source`, `firstAcceptedAt` (Unix-секунды UTC). Решённой считается уникальная пара `(contestId, index)` с импортированным `OK`; повторные успешные посылки не увеличивают `solvedCount`. В отчёт включаются все заведённые участники, в том числе с нулём решений. Имена берутся из сохранённых профилей и могут быть пустыми. Участники отсортированы по числу решений по убыванию, затем по хендлу.

Источником статистики служит протокол посылок Codeforces для хендлов, заведённых в ETRX. Счётчик `solvedCount` в каталоге показывает общее число решивших на Codeforces. Чтобы получить число решивших среди своих участников, посчитай строки статистики с `solved=true` по каждой задаче.
